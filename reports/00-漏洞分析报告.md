## 漏洞详情

### 1. SQL注入 — checklogin.php (严重)

```php
// 原始代码第10行
$check_user="select * from master WHERE admin='$username'AND creds='$password'";
```

`$username` 和 `$password` 直接拼入SQL，无任何过滤。攻击者输入 `' OR 1=1 -- ` 即可绕过认证登录后台。

### 2. SQL注入 — handshake.php (严重)

```php
// 原始代码第33行
$insert_user="insert into victims (...) VALUE ('$machine_name','$computer_user',...)";
```

所有POST参数直接拼接，攻击者可注入任意SQL，篡改或删除victims表数据。

### 3. SQL注入 — dashboard.php (严重)

```php
// 原始代码第70行
$total_pages_sql = "select count(*) from victims where (machine_name like '%$search%') ...";
// 原始代码第79行
$query="select * from victims where (machine_name like '$%search%') ...";
```

搜索参数 `$search` 未过滤直接拼入SQL。可通过搜索框注入提取任意数据。

### 4. 任意文件读取 — download_file.php (严重)

```php
// 原始代码第6、16行
$file=$_GET['file'];
readfile($file);
```

`$file` 参数未做路径校验，攻击者可传入 `../../etc/passwd` 读取服务器任意文件。

### 5. 路径遍历+目录创建 — handshake.php (高)

```php
// 原始代码第22-29行
$password_folder_name = $machine_name. '_' .$computer_user;
mkdir ('./passwords/' . $password_folder_name);
file_put_contents("./passwords/{$password_folder_name}/". $password_file_extension , $password);
```

`$machine_name` 和 `$computer_user` 可含 `../`，在服务器任意路径创建目录和写入文件。

### 6. 反射型XSS — dashboard.php (高)

```php
// 原始代码第102-113行
// $machine_name、$computer_user 等从数据库取出后直接输出到HTML
echo "<td>".$machine_name."</td>";
```

存储在数据库中的恶意脚本会在管理员查看dashboard时执行(存储型XSS)。

### 7. 硬编码数据库凭据 — db_conection.php (高)

```php
$dbcon=mysqli_connect("localhost","jasminadmin","123456");
```

用户名 `jasminadmin`、密码 `123456` 硬编码在源码中。应使用环境变量或配置文件。

### 8. 明文密码存储 — jasmin_db.sql (高)

```sql
INSERT INTO `master` (`id`, `admin`, `creds`) VALUES (1, 'siddhant', '123456');
```

管理员密码明文存储，应使用 `password_hash()` / `password_verify()`。

### 9. 硬编码握手密钥 — handshake.php (中)

```php
if ($check=="jasmin@123")
```

握手认证密钥硬编码，任何阅读源码者均可伪造受害者数据。

### 10. 认证绕过 — dashboard.php / download_file.php (中)

```php
if(!isset($_SESSION['username'])){
    header("Location: login.php");
}
// header() 之后无 exit()，代码继续执行
```

`header()` 重定向后未调用 `exit()`，攻击者忽略重定向即可访问受保护内容。

### 11. HTTP资源加载 (低)

login.php 和 index.php 通过HTTP加载 Google Fonts 和 jQuery，存在中间人攻击风险。

### 12. CSRF无防护 (中)

所有表单均无CSRF token，攻击者可构造恶意页面诱导已登录管理员执行操作。

---

## 修复方案摘要

| 漏洞 | 修复措施 |
|------|----------|
| SQL注入 | 全部改用 PDO 预处理语句 |
| 任意文件读取 | 白名单校验 + realpath() 限制目录 |
| 路径遍历 | 过滤文件名特殊字符(仅允许字母数字下划线) |
| XSS | 所有输出使用 htmlspecialchars() |
| 硬编码凭据 | 迁移至 .env 配置文件 |
| 明文密码 | 使用 password_hash/verify |
| 认证绕过 | header() 后加 exit() |
| HTTP资源 | 全部改为HTTPS |
| CSRF | 添加 CSRF token 机制 |
