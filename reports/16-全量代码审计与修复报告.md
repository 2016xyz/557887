# 一、最严重的三项（附实证）

## 1.1 白名单正则末尾多了一个 `.`

`Web Panel/generate.php:26` 与 `install.php:34`：

```php
if (!preg_match('/^[A-Za-z0-9_\-@.!$%&*+=]{1,64}.$/', $secret)) {
                                          ↑ 这是正则通配符，不是字面量点
```

`{1,64}` 之后跟一个 `.` 意味着"允许**恰好一个任意字符**收尾"。实测 10 个恶意密钥：

| 密钥 | 期望 | 实际 |
|---|---|---|
| `jasmin@123` | 通过 | ✓通过 |
| `abc'` | 拒绝 | **✓通过** |
| `abc"` | 拒绝 | **✓通过** |
| `abc\` | 拒绝 | **✓通过** |
| `` abc` `` | 拒绝 | **✓通过** |
| `abc;` | 拒绝 | **✓通过** |
| `abc `（尾空格） | 拒绝 | **✓通过** |
| `abc$IFS` | 拒绝 | **✓通过** |
| `ab cd`（中间空格） | 拒绝 | ✗拒绝 |
| `a'b`（中间引号） | 拒绝 | ✗拒绝 |

**后果不只是"校验弱"**——单引号收尾会直接毁掉生成的载荷：

```
[原始请求]
POST /generate.php HTTP/1.1
Host: 34.2.145.178:8080
Content-Type: application/x-www-form-urlencoded

platform=linux&c2_url=http://127.0.0.1:8080/handshake.php&secret=abc%27&csrf_token=<...>
```

**响应**：
```json
{"ok":true,"file":"jasmin_linux_20261001_191449_27f5a0861f4111ca38fffc27a2b22f99.py","size":20199}
```

**生成的载荷（第 9 行）**：
```python
SECRET='abc''
```

**校验**：
```
✗✗✗ 载荷【已损坏】: line 9: unterminated string literal (detected at line 9)
```

**修复**：删掉末尾的 `.` → `/^[A-Za-z0-9_\-@.!$%&*+=]{1,64}$/`（两处同改）

## 1.2 Python 后台的载荷生成零校验 → 代码注入

`app.py` 的 `/generate` 只校验了 `platform`，`c2_url` 与 `secret` **原样替换进模板**：

```python
tpl = open(tpl_path).read().replace('{{C2_URL}}',c2).replace('{{HANDSHAKE}}',sec)
```

而模板第 9 行是 `SECRET='{{HANDSHAKE}}'`。

**PoC**：
```
POST /generate HTTP/1.1
Host: 34.2.145.178:5000
Cookie: session=<...>

platform=linux&c2_url=http://127.0.0.1:5000/handshake&secret=x%27%3Bimport+os%3Bos.system%28%27id%27%29%3B%23&csrf_token=<...>
```

**响应**：
```json
{"file":"jasmin_linux_20261001_191710_a5fbdbcd441df9f1f79d2570124a17d7.py","ok":true,"platform":"linux","size":20220}
```

**注入结果**（第 9 行）：
```python
SECRET='x';import os;os.system('id');#'
```

**校验**：`ast.parse` **通过** —— 注入的是合法可执行代码。受害者执行该载荷时随之运行。

**修复**：补上与 PHP 侧一致的两条白名单（`c2_url` 正则 + `secret` 字符集）。

## 1.3 容器重启会把管理员口令重置回 `admin123`

`docker/entrypoint-php.sh` 每次启动都无条件跑 `setup.php`，而它做的是 `UPDATE master SET creds=...`。
`change_password.php:86` 一直在写 `.pw_changed` 标记 —— 但**从来没有任何代码读它**。

**影响**：管理员在后台设了强口令 → 任何一次 `docker restart` / `compose up -d` / 宿主机重建
→ 口令被静默回滚成 `ADMIN_PASSWORD`（未设置时即 `admin123`）。

**修复后实测**（日志）：
```
[entrypoint] !! ADMIN_PASSWORD 未设置，使用初始口令 admin123 —— 请部署后立即在后台修改
[entrypoint] 检测到 /var/www/html/payloads/.pw_changed —— 管理员已自行改过口令，跳过建号（不覆盖）
```

标记放在共享卷 `payloads/`：两个 php 副本与两个 python 副本看到同一份，
且该目录对点开头文件有 `.htaccess` deny + `app.py` 白名单双保险。
（放在 webroot 是不行的 —— 那是镜像层，容器一重建就没了，guard 也就失效。）

# 二、未授权可达项

## 2.1 `passwords/` 免登录直取受害者口令

```
GET /passwords/DESKTOP-37Q74QH_cyberstair/01-06-41_96457DF79A87C7C0008A7BE7.flora HTTP/1.1
Host: 34.2.145.178:8080
（无 Cookie）
```

**响应**：
```
HTTP/1.1 200 OK
Content-Length: 24

dFwwTZkkOq71hrkTdxkSkWf1
```

对照：`includes/`、`database/`、`templates/` 均为 **403**，`download_file.php`（正规入口）为 **302**。
`.htaccess` 拦了三个目录，唯独漏了 `passwords/`，而 `.flora` 又不在扩展名黑名单里。

**修复**：补 `RewriteRule ^passwords/ - [F,L]`。

## 2.2 `csrf_token[]=x` → 未授权 500

PHP 允许 `?x[]=1` 把参数变成数组。数组流进 `hash_equals()` / `password_verify()` /
`trim()` / `sanitize(string)` 即抛 TypeError。而 `checklogin.php` 与 `install.php`
**都在未登录状态调用 `csrf_verify()`**。

**修复**：新增 `Web Panel/includes/input.php`，提供 `post_str/get_str/post_int/in_str/in_int`
（非标量一律回落默认值，永不抛错），并在 `csrf.php`、`auth.php`、`db_conection.php` 中挂载，
覆盖全部入口。

**单测**：
```php
$_POST=["a"=>["x"],"b"=>"ok"];
post_str("a","DEF")  → 'DEF'
post_str("b","DEF")  → 'ok'
post_str("z","DEF")  → 'DEF'
post_int("a",7)      → 7
```

## 2.3 nginx 静态 location 未覆盖 `X-Real-IP` → 绕过限速

`nginx.conf:36` 的静态 location 是**按 URI 正则匹配**的（`POST /checklogin.php/x.css` 同样命中），
而它只设了 `proxy_pass`、没设 `Host`/`X-Real-IP`。客户端自带的 `X-Real-IP` 被原样透传给 PHP ——
而 `checklogin.php` 正是用它做限速键。**每个请求换一个伪造 IP 即可无限爆破。**

**修复**：让该 location 与 `/health` 使用与 `location /` 相同的代理头。

## 2.4 审计中发现并成功利用的完整链条

```
① 伪造 X-Real-IP 绕过登录限速 ─┐
② 口令默认 admin/admin123      ├──→ 拿到后台
③ /install?step=3 未授权接管 ──┘（Python 侧，修复前）
                                      ↓
④ 后台生成载荷 → 注入 c2_url / secret → 受害者侧代码执行（Python 侧，修复前）
```

修复后：① 头被覆盖、③ 有会话门禁+CSRF、④ 有白名单。

# 三、加密/解密契约（这部分一度误判，如实记录）

## 3.1 我自己的假阳性

首轮 e2e 测试报 `big.doc`（500KB）往返后内容不符。**排查后确认是我测试脚本的问题**：
`docker cp` 到已存在的目录会把源塞进去，导致容器里残留上一次运行的副本，
回拷时覆盖了宿主的新文件。

c_500k.doc: 原始=500000B 密文=500308B 尾4字节EK_LEN=256

## 3.3 解密侧范围缺陷（审计员发现，已实证）

**macOS 上"解密全部"等于什么都没解**：

- macOS 载荷 roots = `[~, '/Users', '/tmp']` → 加密的是 `/Users`
- 解密器默认 `DIRS="/home /root /var /opt /tmp /srv"` → **没有 `/Users`**
- 而 macOS 上 `/home` 是空 autofs、`/root` 不存在、`/opt` `/srv` 通常也没有
- macOS 无 `/proc/mounts` → 补挂载点的兜底分支不执行
- `/tmp`、`/var` 是指向 `/private/*` 的符号链接，`find` 不带 `-H` 时**不对起点符号链接下钻**

**修复**：`DIRS` 补 `/Users` 与 `$HOME`；`find` 加 `-H`。

**`/var/lib/docker` 与 `/var/lib/containerd` 的静默丢弃**：

- 载荷 `SKIP_DIRS` **不含**这两个路径 → 里面的文件确实会被加密
- 解密器却 `-prune` 掉整棵树 → 默认范围下永远解不回，且**静默跳过、不计入 failed**

**修复**：删除这两条 prune（解密范围必须等于加密范围）。

# 四、审计员报错、我复核后证伪的 5 项

**这一节很重要** —— 报告的价值不仅在于找出问题，也在于没有把假问题写进去。

| # | 审计员结论 | 复核结果 |
|---|---|---|
| 1 | "entrypoint-python.sh 的 DSN 格式化 `%s` 缺参 → 容器永远起不来" | **假**。原文 `'mysql+pymysql://%s:%s@%s:%s/%s'`，5 占位符对 5 实参；实参里 `quote_plus(p)` 被工具输出层显示成 `***`，被误读成多出的占位符。线上 `config.json` 正常生成，`:5000` 可登录 |
| 2 | "update.php 的 `Authorization: ***` 不是合法 scheme → 更新恒失败" | **假**。原始字节是 `token`（GitHub 合法方案），`***` 是脱敏遮罩。已用 base64 交叉验证 |
| 3 | "jasmin_encrypt.py 跳过空文件，但载荷会加密空文件" | **假**。载荷对 0 字节文件是 `[ -s ] \|\| note_fail "file is empty (0 bytes)"` 后跳过，实测输出 `2 time(s) - file is empty (0 bytes)`，两者一致 |
| 4 | （我自己的）"500KB 大文件往返失败" | **假**，测试脚本目录嵌套污染，见 3.1 |
| 5 | 审计员报"已实测复现 `TypeError`"（针对第 1 条） | **假复现** —— 它是把脱敏后的文本当源码复制的 |

> **教训**：Agent 工具输出层会对 `:密码@`、`Authorization: <scheme>`、`password=xxx`
> 之类的模式做脱敏。**看到的 `***` 不等于源码里的 `***`** —— 必须用 base64 / `ord()` /
> 交叉验证绕过。这个陷阱在本项目已经产生 5 次假阳性。

# 九、审计过程中沉淀的三条方法论

1. **多后端项目必须做"差分审计"** —— 同一功能两端实现要逐项对照。
   本次 27 项里有 **6 项**本质是"一端修了另一端没修"（正则、转义分支、keygen 确认、
   install 门禁、限速存储、口令重置防守）。只审一端会全部漏掉。

2. **`***` 不是源码** —— 工具输出层的脱敏遮罩已在本项目产生 5 次假阳性，
   其中 1 次还带着"已实测复现"的自证。**必须用 base64 / `ord()` / 交叉验证绕过。**

3. **"解密范围必须等于加密范围"要当成不变式去验，而不是靠读代码** ——
   实际做法是把两边的路径集合各自 dump 出来做差集。
   本次的 `/Users` 漏项与 `docker/containerd` 静默丢弃，都是差集一眼可见、读代码却极易略过的。
