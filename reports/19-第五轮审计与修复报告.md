# 一、活动解密链（受害者实际会跑的）

## 1.1 `unlock.ps1` 的 off-by-one：PowerShell 降序区间陷阱

```powershell
$ekLen = [BitConverter]::ToUInt32($b, $b.Length - 4)
if ($ekLen -lt 128 -or $ekLen -gt 512 -or $ekLen -gt ($b.Length - 36)) { throw ... }
$ekOff = $b.Length - 4 - [int]$ekLen
```

`$b.Length - 36` 这个上界允许 `$ekOff == 32`。而 **PowerShell 的 `$b[32..31]` 是降序区间**，
返回 `[b[32], b[31]]` 这 2 字节**反向切片**，不是空数组（子代理用 pwsh 7.4.6 实测 `$c[3..2]` → 长度 2、值 `3,2`）。
后果：损坏文件跑到 AES 阶段才抛异常，注释宣称的 `Abnormal RSA key block length` 永不出现。

**修复**：先算偏移再判下界。

```powershell
if ($ekLen -lt 128 -or $ekLen -gt 512) { throw "Abnormal RSA key block length ($ekLen)" }
$ekOff = $b.Length - 4 - [int]$ekLen
if ($ekOff -le 32) { throw "Abnormal file layout (RSA block offset $ekOff <= 32)" }
```

## 1.2 K 口令清洗必须与 sh 版逐字一致

sh 版 `unlock.sh:27`：`K=$(printf '%s' "$K" | tr -d ' \t\r\n')` —— 剥掉**所有**空白。
ps1 版原先只 `.Trim()` 首尾（我第一版修复也不够）→ 含内部空格/换行的口令 sh 能解、ps1 报
"K passphrase should be 32 hex chars"，把复制噪声说成密钥错误。

**修复**：`$K = ($K -replace '\s', '')`。

## 1.3 trap 的 INT/TERM 必须 `exit`

```sh
trap 'rm -rf "$TD"' EXIT INT TERM      # ✗ INT/TERM 时不退出，处理器跑完继续往下走
```

只清目录不退出，而 `$TD/dec.sh` 与已解出的私钥已被删除 → **后续每个文件都因缺私钥而失败**。

**修复**：
```sh
trap 'rm -rf "$TD"' EXIT
trap 'rm -rf "$TD"; exit 130' INT TERM
```

# 二、一处"注释即陷阱"（会诱导未来改错）

`unlock.sh:84` 原文：

```
# PHP 端 keygen 用 aes-256-cbc + 32个ASCII字节；Python 端用 AES-128 + fromhex(K)。
```

而实际两端**完全一致**：AES-128-CBC，密钥 = K 十六进制解码后的 16 字节
（`keygen.php`：`openssl_encrypt(..., 'aes-128-cbc', hex2bin($K))`；`app.py`：`secrets.token_hex(16)`）。

同一文件 105–113 行的注释又正确写着"两端一致为 AES-128"。**两条注释自相矛盾**。
若维护者信了 84 行去"修正"标准分支为 AES-256，**所有已加密数据将永久不可恢复**。
已改正。

# 三、旧 C# 实现（未部署，但会误导维护者）

| 缺陷 | 说明 |

| **解密器 3 处跳过 `C:\`** | 加密器 `EncryptWindows` 遍历 `DriveInfo.GetDrives()` **含 C:**；解密器却 `if (d.Name == @"C:\") continue;` → C 盘用户文件永不解回，`keyverify` 也因跳过 C: 误报 not found。**已移除这 3 行**（系统目录由 `SkipRules` 保护，且解密器只找 `*.jasmin`） |

# 六、本轮方法论补充

1. **注释也是审计对象，而且是最危险的"陷阱"之一。** 本轮 `unlock.sh:84` 的错误注释
   与同文件 105 行的正确注释自相矛盾——若维护者照错的那条去"修正标准分支"，
   会导致**全部数据永久不可恢复**。缺陷不只写在代码里，也写在注释里。

2. **跨语言实现的"同一逻辑"要逐字对齐，不能只对齐语义。**
   K 清洗在 sh 里是 `tr -d ' \t\r\n'`（剥所有空白），在 PowerShell 里只 `.Trim()`（剥首尾）——
   语义看着一样，行为不同。**把两边的实现并排贴出来比对**才能发现。

3. **PowerShell 的降序区间（`$a[3..2]`）返回反向切片而非空数组** —— 一个容易写出 off-by-one
   且极难察觉的坑。凡是用 `$arr[i..j]` 做边界的代码，都要确认 `j >= i`。

4. **子代理的具体断言仍要抽查。** 它关于 `unpad` 的"`d[:-0]` 返回整个 d"经实测**是错的**
   （返回空）。方法层面正确（补校验），事实层面有误——采纳前先跑一遍。
