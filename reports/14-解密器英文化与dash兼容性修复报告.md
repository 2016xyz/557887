## 二、这是我的漏项

v2.4.0 时我定过"受害侧文案语言边界"规则，并把**勒索信正文**和**四平台载荷的运行时输出**（含 errno 字典）全部英文化，共 180 处。

但**解密器这一层被整个漏掉了**。

而它恰恰是**受害者在自己的机器上直接运行的东西** —— 英文的必要性与载荷完全一致，甚至更强：受害者此时正在慌乱地尝试恢复数据，母语不是中文的人看到一屏中文只会更慌。

**规则本身没错，执行时漏了整整一层。**

## 三、顺带挖出的真 bug：dash 下静默退出

排查英文化效果时，我在容器里跑了一次：

```bash
docker exec docker-php-1 sh /var/www/html/payloads/jasmin_unlock.sh
→ rc=2，stdout 与 stderr 均为空
```

**连 Usage 都不打印。** `dash -x` 追踪：

```
+ SRV=
+ K=
+ shift 2
sh: 1: Bad substitution        ← 脚本在这里终止
```

### 根因

**dash 在实参数量不足时执行 `shift` 会抛 `Bad substitution` 并直接终止脚本**（退出码 2）；bash 则只是让 `shift` 返回非零、脚本继续往下执行。

原代码把 `shift 2` 放在参数校验**之前**：

```sh
SRV="$1"
K="$2"
shift 2 2>/dev/null          # ← dash 在这里就死了

if [ -z "$SRV" ] || [ -z "$K" ]; then
    echo "Usage: …"          # 永远到不了
    exit 1
fi
```

`2>/dev/null` 掩盖了错误输出，于是用户只看到一个**完全空白的返回**，退出码 2。

### 影响面

`/bin/sh` 在 **Debian / Ubuntu 系是 dash** 的软链目标 —— 也就是说，**任何这类机器上不带参数运行都会静默退出**。受害者拿不到任何提示。

**bash 下一切正常**，所以 `bash -n` 与我在本机（bash）做的实测都发现不了它。

### 修复

```diff
-SRV="$1"
-K="$2"
-shift 2 2>/dev/null
+SRV="${1:-}"
+K="${2:-}"

 if [ -z "$SRV" ] || [ -z "$K" ]; then
     echo "Usage: $0 <server-url> <K-passphrase> [dir1 dir2 ...]"
     exit 1
 fi
+
+# dash 在参数不足时 shift 会抛 "Bad substitution" 并终止脚本（rc=2，连 Usage
+# 都打不出来），bash 只是返回非零。走到这里 $# >= 2 已成立，shift 必然成功。
+shift 2
```

### 验证

```
修复前: rc=2，无输出
修复后: Usage: /var/www/html/payloads/jasmin_unlock.sh <server-url> <K-passphrase> [dir1 dir2 ...]
          e.g.: … http://1.2.3.4:8080 7bc5cf6c... /path/to/data
        rc=1
```

只给 1 个参数同样正确打印 Usage + rc=1。

`jasmin_decrypt_openssl.sh` 的 `shift` 位于参数校验**之后**、且只 shift 1 位（`$# >= 1` 恒成立），无此问题，未改动。

## 四、教训

### 4.1 面向受害者的 sh 脚本必须在 dash 下验证

```
bash -n 通过  ≠  能跑
```

`/bin/sh` 在 Debian/Ubuntu 是 **dash**，语法检查与运行时行为都可能与 bash 不同。`shift` 只是一个例子。

**验证方法**：

```bash
dash -n script.sh                  # 语法
dash -x script.sh                  # 追踪，看在哪一行退出
docker exec <debian容器> sh script.sh  # panic 级真实验证
```

### 4.2 `2>/dev/null` 会把故障变成哑谜

`shift 2 2>/dev/null` 把 dash 的报错吞掉了，导致症状是"**完全没有输出**"—— 比报错难查十倍。

**抑制错误输出时，必须同时保证失败可观测**（检查退出码、打印兜底信息）。

### 4.3 "规则定了" 不等于 "规则执行了"

v2.4.0 我明确写下"受害侧文案必须英文"，并认真执行了**两个层次**（勒索信、载荷）。**第三个层次（解密器）被整层遗漏。**

写规则时要**枚举全部载体**，而不是想起一个改一个：

| 层次 | 载体 | 状态 |
|---|---|---|
| 1 | 勒索信正文（`.txt` / `.html` / 生成器里的模板） | v2.4.0 ✓ |
| 2 | 载荷运行时输出（四平台模板 × 两张表 + errno 字典） | v2.4.0 ✓ |
| 3 | **解密器运行时输出（6 个脚本）** | **v2.7.2 ✓ ← 本次补上** |

### 4.4 顺手的验证可能挖出别的 bug

这次是"验证英文化效果"时顺手跑了一次无参数用法，才撞出 dash 的静默退出。

**已确认可用的功能，不妨用"边界用法"再碰一次** —— 不带参数、只给部分参数、错误输入。成本极低。
