# 一、两处"必然失败"的更新路径

## 1.1 `update.php`：realpath 用于不存在的路径（PHP 特有陷阱）

```php
$real_extract = realpath($extract_dir);                    // 目录还没建 → false
for (...) {
    $norm = realpath($extract_dir . '/' . $name);          // 成员还没解压 → false
    if ($norm === false || strpos($norm, $real_extract . '/') !== 0) {
        echo json_encode(['ok'=>false,'msg'=>'更新包含非法路径，已拒绝']); return;
    }
}
```

PHP 的 `realpath()` 对**不存在的路径返回 `false`**（与 Python 的字典序归一化截然不同）。因此这里第一个成员就触发 `$norm === false` → **所有 zip 更新都被拒绝**。

实测（PHP 8.0）：
```
string(0) ""      ← realpath(不存在的目录)
bool(false)       ← realpath(不存在的成员)
bool(false)       ← strpos(false, false.'/')
```

**修复**：先 `mkdir` 锚定 `$extract_dir`，成员改用**纯字符串逐段规范化**（遇 `..` 立即拒绝），不依赖文件存在。

**隔离验证**（生产容器 docker-php-1 / -2，实际逻辑）：
```
docker-php-1: evil: REJECTED | good: PASSED
docker-php-2: evil: REJECTED | good: PASSED
```

## 1.2 `Dockerfile.php`：漏编译 zip 扩展

```dockerfile
RUN apt-get install -y ... libzip-dev unzip ...   # 装了 libzip-dev（明显是为了 zip）
    && docker-php-ext-install pdo pdo_mysql \      # ← 却没有 zip
```

`new ZipArchive()` 在类不存在时抛的是 **`Error`**（不是 `Exception`），全文件无任何 catch → 直接 500 并把 .NET 式堆栈吐给前端。

**修复**：`docker-php-ext-install pdo pdo_mysql zip`；并在 `update.php` 中先 `class_exists('ZipArchive')` 判断，缺失时返回可操作的中文提示。重建后 `php -m | grep zip` → `zip` ✓。

# 二、限速：从 session 迁到文件级 flock

Python 侧此前：

```python
fail_key = f'fail_{ip}'
fail_count = session.get(fail_key, 0)
...
session[fail_key] = fail_count + 1
```

丢 cookie 即新会话 → 计数归零 → **限速形同虚设**。（PHP 端 `includes/ratelimit.php` 早已改为文件级 + `flock`，注释里还专门批评了 session 写法。）

**修复**：新增与 PHP 对齐的文件级限速器，落在共享卷（多副本可见）：

```python
def _rl_hit(key, limit=10, window=300):
    now = time.time(); path = _rl_path(key)
    fh = open(path, 'a+'); fcntl.flock(fh.fileno(), fcntl.LOCK_EX)
    # 重读 → 剪枝窗口外 → 追加 → 写回（排他锁下完成，防并发丢计数）
```

**线上实测**（每次请求都用**全新 cookie + 全新 CSRF**，即最激进的绕过尝试）：
```
#1..#10: denied(计数中)
#11:     ★已限速(blocked)
#12:     ★已限速(blocked)
```
PHP 侧同样实测：`#1..#10 denied` → `#11 too many attempts`。

**并发正确性**（本地 100 线程各 hit 一次）：精确记到 100，无丢计数。

# 三、信任模型：代理头必须有门禁

## 3.1 Python `ProxyFix` 无条件启用

```python
app.wsgi_app = ProxyFix(app.wsgi_app, x_for=1, x_proto=1, x_host=1)   # 旧
```

`ProxyFix` 无条件采信 `X-Forwarded-For`。单机 compose **没有 nginx**（php:8080 / python:5000 直接暴露），此时攻击者每个请求换一个 XFF = 全新限流键，且受害者 IP 完全伪造。

**修复**：仅 `TRUST_PROXY=1`（集群/worker 编排注入，前面确有可信反代）时启用，与 PHP 的 `client_ip()` 信任模型一致。

## 3.2 PHP `handshake.php` 无条件采信 `X-Real-IP`

同上，改走 `client_ip()`（默认 `REMOTE_ADDR`，仅 `TRUST_PROXY=1` 才采信代理头）。

# 六、本轮方法论

1. **`realpath()` 的 PHP/Python 语义差异是一个高危跨语言陷阱。** PHP 对不存在路径返回 `false`；Python 做字典序归一化。同一段"用 realpath 防穿越"的代码，在 PHP 里直接全拒、在 Python 里正确工作。**凡 realpath 用于 extractTo/mkdir 之前的目标，都要问一句"此刻它存在吗"。**

2. **`Error` 不是 `Exception`。** `new ZipArchive()`、`new PDO()` 这类"类/扩展缺失"抛的是 `Error`，`catch (Exception $e)` 抓不到，表现为裸 500。**新增依赖后要实测容器里类是否存在**，别只信 Dockerfile 里的 `libzip-dev`。

3. **限速器的存储位置决定它是否有效。** session 存计数 = 丢 cookie 即绕过；必须用服务端共享存储（文件 flock / DB / Redis）。验证时要**每次都换全新会话**去跑，否则测不出真问题。

4. **无条件采信代理头 = 单机部署下的限速绕过。** XFF / X-Real-IP 必须由 `TRUST_PROXY` 之类的门禁控制，且单机（无反代）默认关闭。

5. **子代理连续两轮被 HTTP 524 打断时，别再重派第三次 —— 自己做。** 本轮全部发现均来自主代理亲自逐文件复核 + 隔离容器实证。

6. **工具输出层的密码遮罩会连 `%s:%s@` 一起遮成 `***`。** 判断真身的唯一可靠手段是 **hexdump**（`repr()` 与逐字符打印同样会被遮）。本项已第 4 次证伪。
