## 二、为什么是 3.0.0（主版本号）

本版本跨度对应此前两个提交所引入的**破坏性 / 底层性变更**，按语义化版本应当升主版本号：

| 提交 | 内容 | 为何属主版本级 |
|---|---|---|
| `bb7e67d` | Windows 兼容 + 全量安全加固 + 后台 UI/UX（25 文件，+3582/−31） | 新增 `includes/platform.php` 跨平台抽象层，替换全站 `chmod`/`mkdir`/`sys_get_temp_dir`；新增 `router.php`/`web.config` 部署形态；默认部署方式改变 |
| `9997605` | Windows 载荷「无法运行」根因修复（8 文件，+407/−9） | **投递命令外壳由 cmd/batch 改为 PowerShell 原生**（`$env:TEMP`、`$exe` 变量、`#` 注释、csc 路径三级回退）——操作方式与旧版不兼容 |

即：升级到 3.0.0 后，**载荷投递命令与部署方式与 2.x 不兼容**，符合 MAJOR 定义。

## 四、升级方式

### 后台一键更新
面板内置更新检查读取 `https://raw.githubusercontent.com/2016xyz/Jasmin-Ransomware-Private/master/VERSION`，
两个面板的 `REPO` 常量均已确认指向本仓库：

- `Web Panel/update.php:13` —— `define('REPO', '2016xyz/Jasmin-Ransomware-Private');`
- `Web Panel Python/app.py:871,974` —— 同样指向 `2016xyz/Jasmin-Ransomware-Private`

> 若此前配置过指向旧名 `2016xyz/Jahfdgerif` 的值，本版本已统一为规范名。

### 手动升级
```bash
git pull origin master
```
随后确认 `VERSION` 与 `Web Panel Python/VERSION` 均为 `3.0.0`。

### Docker
`docker/Dockerfile.php:14` 与 `Dockerfile.python` 会 `COPY VERSION` 进镜像，
重建镜像即自动携带新版本号：
```bash
docker compose -f docker/docker-compose.yml build
```

## 五、兼容性说明

| 项 | 2.x | 3.0.0 |
|---|---|---|
| Windows 载荷投递命令 | cmd/batch（`::` 注释、`%TEMP%`） | **PowerShell 原生**（`$env:TEMP`、`#` 注释、csc 三级回退） |
| 跨平台文件权限 | 全站裸 `chmod`（Windows 上失败） | `includes/platform.php` 抽象（Windows 跳过） |
| 部署入口 | 无 | `router.php`（php -S）/ `web.config`（IIS）/ `.htaccess`（Apache） |
| 静态资源防泄漏 | 无 | `.htaccess` + `router.php` + `web.config` 三重拦截 |
| 配置文件 | 硬编码于源码 | `.env`（模板 `.env.example`） |

**破坏性变更**：2.x 时代手工写好的 cmd 投递命令在 3.0.0 下不再适用，需改用面板生成的新命令。
